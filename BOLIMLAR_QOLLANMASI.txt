================================================================================
MASSAJ CRM — BO‘LIMLAR VA KUNDALIK ISH QO‘LLANMASI
================================================================================
Yangilangan sana: 23.11.2026
Asos: joriy frontend kodi va serverning tekshirilgan Swagger hujjati.
Joriy topshiriq: faqat frontend. Backend keyingi alohida bosqichda bajariladi.

LOYIHA HOLATI
Bu repo React frontend hisoblanadi. Server manzili .env orqali ulanadi.
Menyular va formalar bir kishi ishlaydigan markazga moslashtirildi.
Xizmat biriktirish, qabul yaratish va davomatdan avtomatik hisoblash uchun
serverda yangi API kerak. Shu APIlar ulanmaguncha tegishli saqlash tugmalari
faol bo‘lmaydi. Interfeysning mavjudligi server amali tayyorligini bildirmaydi.
Backend bo‘yicha aniq vazifalar BACKEND_ULASH_TALABLARI.txt da yozilgan.

1. EGASINING ISH KABINETI
--------------------------------------------------------------------------------
SUPER_ADMIN yoki ADMIN bitta kabinetdan boshqaruv va klinik ishni yuritadi.
Mutaxassis kabinetiga o‘tish yoki rol almashtirish talab qilinmaydi.
Alohida SPECIALIST kabineti olib tashlangan. Egasi SUPER_ADMIN yoki ADMIN
hisobi bilan ishlaydi; mustaqil SPECIALIST hisobi 403 sahifasiga tushadi.

Asosiy menyu — 9 ta bo‘lim:
  Dashboard          /dashboard/super-admin
  Ota-onalar         /dashboard/super-admin/parents
  Bolalar            /dashboard/super-admin/children
  Qabul va davomat   /dashboard/super-admin/attendance
  Xizmatlar          /dashboard/super-admin/services
  Kassa              /dashboard/super-admin/cash
  Qarzdorlar         /dashboard/super-admin/debtors
  Hisobotlar         /dashboard/super-admin/reports
  Sozlamalar         /dashboard/super-admin/settings

Bildirishnomalar yuqoridagi qo‘ng‘iroq orqali ochiladi.
Profil va parol Sozlamalar ichida joylashgan.
Adminlar, xodimlar va mutaxassislar boshqaruvi sahifalari hamda ularga tegishli
ishlatilmaydigan frontend store/API kodlari olib tashlangan.
Serverdagi avvalgi ma’lumotlar va tarix o‘zgartirilmagan.

2. DASHBOARD
--------------------------------------------------------------------------------
Faol bolalar, bugungi qabullar, bugungi to‘lovlar va oila qarzlari ko‘rsatiladi.
Qabul va Kassa bo‘limlariga tezkor havolalar mavjud.
Qarz jami serverdan olingan oila hisoblariga asoslanadi. Hisob yuklanmagan
bo‘lsa nol o‘rniga “Tasdiqlanmagan” ko‘rsatiladi.
Qabullar API ulanmagan bo‘lsa bu holat aniq yoziladi.

3. OTA-ONALAR
--------------------------------------------------------------------------------
Ota-onaning alohida hisobi, aloqa ma’lumotlari va farzandlari saqlanadi.
Ota-onalar bo‘limi Bolalar bo‘limidan alohida qolgan.
Ota-onani arxivlash tarix va farzandlarini butunlay o‘chirish degani emas.
Ota-ona uchun alohida kabinet saqlangan.

4. BOLALAR VA BOLA KARTASI
--------------------------------------------------------------------------------
Bola qo‘shishda:
  - To‘liq ism, tug‘ilgan sana va jins.
  - Ro‘yxatdagi ota-ona.
  - Ixtiyoriy manzil va qo‘shimcha ma’lumotlar.

Xizmat tanlash bola yaratish uchun majburiy emas.
Muvaffaqiyatli yaratishdan so‘ng bola kartasi avtomatik ochiladi.
Server bola yaratib, ota-onani biriktirishda xato bersa, aniq xabar chiqadi.
Bunday holatda qayta bola yaratmang; mavjud kartadan “Tahrirlash” orqali
ota-onani biriktiring. Bog‘langan ota-onani boshqa oilaga almashtirish server
moliyaviy migratsiyasi tekshirilmaguncha bu formada bajarilmaydi.

Bola kartasida:
  - Umumiy ma’lumotlar va mavjud tarixiy tashxis/allergiya ma’lumotlari.
  - Ota-onaning umumiy depoziti va qarzi.
  - Xizmatlar va seanslar.
  - Qabul va davomat tarixi.
  - Baholashlar.
  - Rivojlanish qaydlari.

Arxivlash profildagi moliyaviy va klinik tarixni yo‘q qilmaydi.

5. XIZMATLAR KATALOGI
--------------------------------------------------------------------------------
Xizmat formasida faqat:
  - Xizmat nomi.
  - Davomiyligi, daqiqada.
  - Bir seans narxi, so‘mda.

Seanslar soni, boshlanish sanasi va haftaning kunlari katalogda kiritilmaydi.
Xizmatni tahrirlash, arxivlash va arxivdan tiklash mavjud API bilan ishlaydi.
Avvalgi seanslarning narxini katalogdagi yangi narx bilan qayta hisoblash
frontendda bajarilmaydi. Server tarixiy narx nusxalarini saqlashi kerak.

6. XIZMAT BIRIKTIRISH
--------------------------------------------------------------------------------
Alohida sahifa yo‘q. Bola kartasi → Xizmatlar va seanslar → Xizmat biriktirish.

Oynada:
  - Faol katalogdan xizmat tanlash.
  - Musbat butun son bilan seanslar soni.
  - Boshlanish sanasi.
  - Kelish uchun haftaning kunlari.
  - Ixtiyoriy qabul vaqti.

Narx va davomiylik tanlangan xizmatdan olinadi.
Vaqt bo‘sh qoldirilsa yashirin 09:00 yoki 10:00 belgilanmaydi.
Bitta bolaga bir nechta xizmat mustaqil seans sonlari bilan biriktirilishi mumkin.
Jami, bajarilgan va qolgan seanslar alohida ko‘rsatiladi.
Qo‘shimcha seans qo‘shish bola kartasidagi mavjud xizmat orqali bajariladi.

HOZIRGI CHEGARA: biriktirish va seans qo‘shish oynalari tayyor; serverdagi
tegishli API mavjud bo‘lmagani uchun yozish amallari hali ulanmagan.
Frontend o‘zida soxta biriktirish yoki moliyaviy natija yaratmaydi.

7. QABUL VA DAVOMAT
--------------------------------------------------------------------------------
Kunlik va haftalik ko‘rinish, sana, bola/xizmat bo‘yicha qidiruv va davomat filtri.
Har qabulda bola, bajariladigan xizmat, davomiylik, narx va ixtiyoriy vaqt bor.
Qabul yaratish faqat bolaning biriktirilgan xizmatidan amalga oshiriladi.
Kelmagan qabulni boshqa sanaga ko‘chirish uchun alohida amal mavjud.

Server ulanadigan oqim:
  Keldi  → xizmat bajarildi; bitta seans sarflanadi, xizmat haqi oila hisobidan
           olinadi va haqiqiy kelgan vaqt serverda saqlanadi.
  Kelmadi → pul yechilmaydi, bajarilgan seanslar soni oshmaydi.
  Keldi → Kelmadi → avvalgi haq qaytarish yozuvi bilan tiklanadi.
  Bir holatdagi izohni tahrirlash → takror pul yechmaydi.

Tanaffus kunlari seans yoki pul sarfi hisoblanmaydi.
Seans soni kalendar kunlari soni emas. Har kuni kelish majburiyligi tizimga
umumiy qoida sifatida yozilmagan; kelish kunlari biriktirishda tanlanadi.
Bir kunda faqat bitta seans bo‘lishi kerak degan sun’iy cheklov yo‘q.

HOZIRGI CHEGARA: eski attendance API qabul/xizmat va atomik hisoblashni
qo‘llamaydi. Uni /charges bilan ketma-ket chaqirish xavfsiz yechim emas.
Yangi server shartnomasi ulanmaguncha “Keldi/Kelmadi” saqlash faol emas.
Avvalgi haqiqiy davomat tarixi bola kartasida ko‘rinadi.

8. KASSA
--------------------------------------------------------------------------------
Ikki ichki bo‘lim:
  Balans to‘ldirish — ota-ona, summa, to‘lov usuli va ixtiyoriy izoh.
  Pul harakatlari — kirim, xizmat haqi, qaytarishlar va boshqa mavjud yozuvlar.

To‘lov usullari: naqd, karta, o‘tkazma. Bu bank orqali avtomatik pul o‘tkazish
integratsiyasi emas, markaz qabul qilgan to‘lovni qayd etish usullari.
To‘lovlar tarixida qidiruv, sana/usul filtri va kvitansiya mavjud.

Oila hisobida barcha farzandlar bitta depozitdan foydalanadi.
Kirim avval qarzni qoplaydi; ortgani depozit bo‘ladi.
Xizmat haqi avval depozitdan sarflanadi; yetmagan qismi qarzga o‘tadi.
Bir vaqtda musbat depozit va musbat qarz javobi oila hisobi deb qabul qilinmaydi.
Xizmat haqi markazning tashqi xarajati sifatida ko‘rsatilmaydi.

HOZIRGI CHEGARA: mavjud to‘lov API childId ni majburiy deb belgilaydi,
so‘m/tiyin birligi ham kelishilishi kerak. Yangi oilaviy to‘lov shartnomasi
ulanmaguncha yangi balans to‘ldirish o‘chirilgan. Tarixni ko‘rish ishlaydi.
Muvaffaqiyatli server javobisiz kvitansiya yoki kirim yaratilmaydi.

9. QARZDORLAR
--------------------------------------------------------------------------------
Kassadan alohida sahifa. Bitta ota-ona bitta qator sifatida ko‘rsatiladi.
Farzandlari, telefon raqami, server tasdiqlagan qarzi va balans to‘ldirishga
havola mavjud. Telefon orqali bog‘lanish mumkin.
Qarz muddati haqidagi mavjud bo‘lmagan sanalar yoki taxminiy kunlar uydirilmaydi.
Hisoblar yuklanmasa “Qarzdorlik yo‘q” deb ko‘rsatilmaydi.

10. HISOBOTLAR VA SOZLAMALAR
--------------------------------------------------------------------------------
Hisobotlar ichida hisobot jadvali va moliyaviy tahlil joylashgan.
Mavjud moliya, davomat, seanslar va bolalar tarixini filtrlash/eksport qilish
saqlangan. Yangi bajarilgan seanslar server tasdiqlagan qabullardan olinadi.
Tarix migratsiyasi va serverdagi yangi hisoblash ulanmaguncha to‘liq yangi
seans hisobotini tayyor deb hisoblamang.

Sozlamalar ichida:
  Markaz — nomi, telefoni, manzili va ish vaqti.
  Profil va parol — mavjud server amallari doirasida.
  Faollik tarixi — serverdan olingan mavjud audit yozuvlari.
SMS, ovoz, eslatma kabi ishlamaydigan lokal sozlamalar va demo tiklash olindi.
Egasining klinik baholash yozishi uchun server haqiqiy specialistId bog‘lanishini
qaytarishi kerak. Boshqa xodimning birinchi IDsi avtomatik tanlanmaydi.

11. OTA-ONA KABINETI
--------------------------------------------------------------------------------
Ota-ona o‘z farzandlari, xizmatlari, kelishlari, qaydlar, to‘lovlari,
umumiy balansi va qarzini ko‘radi. Pul harakatlari uchun alohida ko‘rinish bor.
Boshqa oilaning ma’lumoti frontendda ko‘rsatilmaydi; haqiqiy kirish nazoratini
server ham har bir endpointda bajarishi shart.
Ota-ona xizmat biriktira olmaydi, bola profilini tahrirlay olmaydi,
davomat yoki to‘lovni boshqara olmaydi.
Pul harakatlari va xizmat biriktirishning ota-ona uchun o‘qish APIlari ham
server shartnomasiga bog‘liq. Ulanmagan joyda aniq holat yozuvi chiqadi.

12. ESKI HAVOLALAR
--------------------------------------------------------------------------------
/admins, /employees, /specialists → Sozlamalar / Profil.
/schedule → Qabul va davomat.
/assessments → Bolalar / Baholashlar (bolani tanlash).
/progress, /goals → Bolalar / Rivojlanish (bolani tanlash).
/payments, /balance → Kassa / Balans to‘ldirish.
/transactions → Kassa / Pul harakatlari.
/analytics → Hisobotlar / Tahlil.
/activity-logs → Sozlamalar / Faollik tarixi.
/profile → Sozlamalar / Profil va parol.
Mavjud query parametrlari saqlanadi; kerakli tab/section yangilanadi.
Eski /dashboard/specialist havolalari faqat egasiga yangi kabinetning mos
bo‘limiga yo‘naltiradi. Bu havolalar ota-ona yoki mustaqil SPECIALIST hisobiga
egasining huquqlarini bermaydi. 403 sahifasidan boshqa hisob bilan kirish mumkin.

13. NAMUNA MA’LUMOTLAR VA TEKSHIRUV CHEGARASI
--------------------------------------------------------------------------------
Production store bo‘sh bazani demo bolalar yoki pul harakatlari bilan to‘ldirmaydi.
Eski seed.ts demo bazasi fayli o‘chirilgan; sinov fixturelari faqat testlar uchun.
Noto‘g‘ri ID birinchi topilgan haqiqiy bolaning IDsi bilan almashtirilmaydi.
Moliyaviy ro‘yxatlar birinchi 100 ta yozuv bilan cheklanib qolmasligi uchun
pagination qo‘llanadi. Server sahifalashni bajarmasa, xato qaytariladi.
Eski alohida seans store modeli olib tashlangan. Rivojlanish sahifasi serverdagi
qayd va baholashlarni ko‘rsatadi. Seans hisoboti “Keldi” deb tasdiqlangan,
haqiqiy kelish vaqti mavjud qabullardan tuziladi.

Frontend testlari va build serverdagi moliyaviy tranzaksiyalar, parallel
davomat, migratsiya yoki real qurilmalarda ishlashni o‘z-o‘zidan isbotlamaydi.
Haqiqiy server integratsiyasi uchun BACKEND_ULASH_TALABLARI.txt dagi shartlar
bajarilib, alohida staging sinovlari o‘tkazilishi kerak.
